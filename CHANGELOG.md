# Changelog

All notable changes to **Codayak** are listed here, newest first. Each entry links to the signed installer on the GitHub release page.

Codayak is a free AI coding workbench for Windows 10 and 11, built for .NET and Visual Studio teams — see the [README](README.md) for what it does and the [User Guide](USER_GUIDE.md) for the full reference.

---

## [1.7.0] — 2026-09

- **Download:** [Codayak_Setup_1.7.0.exe](https://github.com/Techniche-Labs/codayak-releases/releases/tag/v1.7.0) — signed by TECHNICHE LABS PTY. LTD.
- **Requirements:** 64-bit Windows 10 (1809) or later / Windows 11 · Microsoft Edge WebView2 Runtime · an API key for at least one supported LLM provider, or an OpenAI-compatible endpoint. **The .NET 8 Desktop Runtime is no longer required** — see Changed.

### Fixed

- **A tool-heavy turn can no longer march the request past the model's context window.** After every tool round Codayak measures the fill from the provider's own reported input tokens and acts in tiers (Settings → Tools → *Context protection*): from 75 % consumed tool results in the current turn are replaced by short stubs, from 90 % older exchanges are compacted too, and at 95 % no further tool results are accepted and the model is told to summarise. Every tool result now ends with a `[Context: N% of W tokens used]` trailer so the model can self-manage; the per-result cap, the section readers' whole-file threshold and the `searchText` window (now ±60 lines around the first match instead of running to end of file) all scale with the model's window instead of fixed constants; and a range already shown in the conversation is refused with an `ALREADY LOADED` pointer. Applies to chat, Team Mode specialist tasks and background workers alike.
- **Creating a file can no longer overwrite an existing one.** CreateDocument refuses an existing target unless an overwrite is explicitly requested, backs the previous version up to `.coda/backups` first and reports the backup path; a blank file name is refused inside a repository.
- **Update check now runs on every start** (then once every 24 hours while Codayak stays open) instead of being skipped when the last check was under a day old — so a new release is noticed the day it ships.
- **'Install for me only' no longer needs administrator rights** — the per-user installer wrote registry values to the machine hive and stopped with access-denied errors ([#3](https://github.com/Techniche-Labs/codayak-releases/issues/3)).
- **Huge tool results no longer crash a session.** Every tool result is capped at 400,000 characters; codebase search shows a ±200-character window around each match, skips minified bundles and files over 2 MB, and never descends into vendored folders (`node_modules`, `bin`, `obj`, `.playwright`, …) regardless of `.codaignore`.
- **Image-to-image no longer falls back silently to plain generation** — only models probed as edit-capable are used, the result states mode/provider/model/reference, and an unresolvable reference name is refused.
- **Team Mode:** specialists reconnect after sleep or a network drop, and a peer whose link drops is parked for a reconnect grace window and re-admitted when it re-dials rather than evicted at once; **Stop** works from any state; failed or cancelled delegated tasks wake the leader instead of waiting for the next chat turn; a specialist that proceeded without an answer to a question can no longer report its task as complete.
- **Team Mode survives a long sleep on either side.** A **leader** no longer waits for a Windows power event to notice its listening socket died (Modern Standby often never delivers one): it verifies and rebinds the socket the moment a peer's link drops (it is expecting the re-dial), when a heartbeat clock gap reveals a sleep/wake, and periodically while any peer is awaiting re-admission — re-advertising on the LAN when auto-advertise is on — so clicking **Join Session** again with the same invite code just works after the machine wakes. A parked peer's 10-minute re-admission window restarts from the wake instant instead of having been consumed mid-sleep, and the 'Listening on host:port' display is now honest: it refreshes after a rebind, and a listener that could not be rebound shows a persistent 'Listener lost — could not rebind port …' warning instead of claiming to listen. A **specialist** that cannot reach the leader no longer gives up after five attempts (~2.5 minutes): after the fast burst it keeps retrying every 2 minutes for up to 60 minutes, a system resume immediately restarts a fresh fast burst, and only after the whole schedule fails does it close the session — cleanly, without the spurious 'Illegal session transition' warning.
- **A specialist's Team page no longer claims 'Connected as Specialist … Connected to <leader>' while the link is down.** During reconnection the panel header shows 'Connection lost — reconnecting…' (then the 2-minute retry schedule) in warning colour, the endpoint line reads 'Last connected to …', and the normal connected presentation returns only on a successful re-handshake — with an honest disconnected state if the whole retry schedule fails.
- **Team Mode auto-detected specialty no longer truncates at a dotted token** — *"an elite C# .NET developer…"* is advertised whole instead of as `Elite C# .` (likewise `Node.js`, `ASP.NET`, `v8.1`, `e.g.`).
- **Trust Engine reports no longer render as a highlighted code block**, and a gate failure is headed `NOT VERIFIED … · gate: <aim>` rather than a misleading `LOW TRUST 75/100`.
- File dialogs open in the folder you last used for that dialog (when it is inside the connected repo), otherwise at the repo root; **Select Repo** opens at the repo's parent.
- The context-meter tooltip always has text.
- **The Trust Engine security scan now reads config files.** Hard-coded credentials in `.json`, `.xml`, `.config`, `.yaml`/`.yml`, `.env`, `.ini`, `.toml`, `.props`, `.targets` and `.pubxml` are found — `"key": "value"`, `key: value` and `KEY=value` shapes as well as `key = "value"` — and a live-looking key in a non-test config file fails the security gate; `appsettings*` connection strings remain exempt and placeholder or test-path values stay informational.
- **Skill editor layout** — the per-skill **Enabled** and **Always apply** checkboxes moved to their own row beneath **Name** and are centred in it, so the **Add**/**Save** button is no longer clipped to a sliver at the editor's right edge.
- **Skills switches work from screen readers and UI automation.** Toggling **Enable skills** or **Allow Codayak to propose skills** through UI Automation's TogglePattern (screen readers, automated testing) previously flipped the box visually without saving the setting or greying the tab; both switches now persist and apply their state however they are toggled, and loading settings into the tab no longer risks a spurious save.
- **Product name in the UI** — remaining user-facing text that still said *Coda* now reads *Codayak*: the Settings → Tools context-protection description, the database-access and factory-reset prompts, tool status lines and tool descriptions, tool results, system-prompt prose, log headers (help-doc, document search/read, database, directory-delete and message-repair tools; the debug-log system text; Team Mode task outcomes).
- **Attachment thumbnails on the sent message too.** Hovering the `📎` chip on a message bubble now shows a popover with every attached path and a ≤ 240 px thumbnail for each attached image (first six per message; a deleted or undecodable image falls back to its path) — previously only the pre-send chip in the input area had the preview.
- **'Settings updated by another Codayak instance' fires for settings changes only.** Another instance's operational writes — system prompt text, last provider/model, toolbar dials, recent repositories, dialog folders, update-check timestamps, node id — are merged silently with no banner and no Settings-tab re-populate; a genuine settings change still shows the banner, and the re-populate now leaves the control you are typing in untouched. The system prompt, provider and model are saved at most once a second instead of on every keystroke.
- **Trust Engine no longer skips the spec check because the advisory judges spent the budget.** The gates' and A6 spec judge's estimates are reserved before lesson adjudication, the judged security review and the style judge are admitted; an advisory judge that cannot fit skips itself (`budget — reserved for spec compliance`), every budget skip names the run's top two spenders, and the lesson adjudicator's estimate now covers its full reply allowance.
- **Every send pays a smaller baseline.** The source-code skeleton threshold (Settings → Repositories) now applies to the baseline — system prompt plus tool schemas — as a share of the model's context window (default 25%; an untouched 80 or 50 migrates once), so the skeleton map engages on large repos on 1M-token models; the team coding-style and PR-review rules are sent once in the system prompt instead of being repeated inside fourteen tool schemas.
- **A trust report with hundreds of findings no longer floods the chat.** Critical and High findings are still always listed in full, but medium and lower findings are now summarised per severity — grouped by rule with a count and the top offending files, the ten worst listed individually, and an exact `N more … findings elided` pointer to the report file that still holds the complete list. In the chat bubble the summary is a collapsible section you can expand for the detail lines. This also stops an 80,000-character findings dump being fed back to the model as a tool result.
- **The attachment popover on a message bubble can now be scrolled.** It stays open while the pointer is over the chip or the popover itself (with a short grace delay), and the mouse wheel scrolls the popover's own content instead of the transcript underneath.
- **Editing an image with OpenAI's dall-e-2 no longer pays for a hidden probe on every attempt.** dall-e-2's edits endpoint requires a square source image, which the standard capability probe isn't — so the probe could never conclude and re-ran (one billed generation) on each edit. dall-e-2 is now probed with a square image, an accepted probe counts as edit-capable, and the result is cached like every other model's.
- **Repairing the image-edit capability cache is now visible in the log.** When entries poisoned by the old too-small probe are purged on load, an Info line in `app.log` says how many were removed instead of them vanishing silently.
- **Editing an image with OpenAI works again.** OpenAI's edits endpoint returns a fixed 1024×1024 output regardless of the input's shape, which the capability probe misread as *cannot edit* — genuinely edit-capable models (gpt-image-1, gpt-image-2) were refused with "generate-only" evidence. A 2xx with an image from OpenAI's edit endpoint now counts as edit-capable, the models the edit auto-select tries come from your fetched model catalogue (so gpt-image-2 is probed instead of the retired dall-e-3/dall-e-2 tier, with the built-in list only as a fallback), and any wrongly-cached *generate-only* verdicts carrying the fixed-size evidence are repaired on load and re-probed.
- **Native web search via xAI and Google no longer times out.** A search run through the LLM provider's own server-side search is an agentic loop that routinely takes longer than the old 15-second budget — xAI and Google searches were killed before the first token arrived while OpenAI happened to fit. The LLM-search deadline is now 60 seconds (plain HTTP search providers keep their fast 15-second budget), a timed-out search names the provider and the elapsed seconds, and the Google request is now logged (key redacted) like the other providers' so a failure is diagnosable from the log.
- **The assistant no longer schedules redundant wake-up timers.** Delegating a task to a Team Mode peer already wakes the leader when the peer finishes, but the AddTask guidance still invited a fallback timer per delegation and one timer per wait — interrupting the chat with needless `⏰ SCHEDULED TASK DUE` fires. The AddTask and DelegateTaskToPeer tool guidance now says a peer delegation needs no timer, AddTask is for waits with no built-in notification, and several pending checks belong in one consolidated task.
- **A tool that failed no longer announces success.** Every tool completion line in the activity block now classifies its result before choosing the verb — a refused file creation reads `Document creation failed: '<file>' already exists…` instead of `Document created: Error: …`, and the same rule now covers Mermaid diagrams, Word documents, image and video generation (a cancelled call reads `Cancelled.`). The result the model sees is unchanged.
- **Searching a reference wiki no longer fails when a different DevOps connection is active.** Each reference wiki now remembers the connection it was loaded from: with one wiki of a platform attached, the wiki tools use that connection automatically instead of the window's active one; with several attached, the injected wiki map names each wiki's connection so the model can pass it explicitly. And a partial connection name — `Lloyds Admin` for `lloydsauctions/Lloyds Admin` — now resolves on any Azure DevOps / GitHub tool when it matches exactly one configured connection; an ambiguous fragment is refused with the matching names listed. Wikis already cached from an earlier version get the same behaviour: a cached wiki with no recorded connection derives it from the wiki's own identity (`ado:Org/Project` / `github:owner/repo`) against your configured connections and writes it back to the cache, so existing users don't have to re-add their wikis.
- **Browser and desktop screenshots are saved to disk, not just shown to the model.** Every `BrowserSnapshot` / `DesktopSnapshot` screenshot is persisted as a PNG under the session output folder's `Screenshots/` directory (`browser_yyyyMMdd_HHmmss.png` / `desktop_…`), the tool result carries `Saved: <path>` so the assistant can embed the capture in a Word document or re-read it with ReadImage, the saved path shows as a clickable link in the tool-activity block, and each capture is listed in the Files Changed fly-out. Old screenshots are swept on startup using the backup-retention window (default 7 days; only Coda-named files are touched).
- **Files created in the session output folder are now clickable and listed.** A generated Word document, diagram, image or screenshot gets an open link in chat — in tool-activity blocks and when the assistant quotes the path in backticks — and appears in the Files Changed fly-out marked `[session output]` with a Show File action, with or without a repository loaded. A document title ending in a dash or em-dash no longer produces a dangling `_-` filename tail.
- **Reduced API cost: conversation history is now served from the provider prompt cache on multi-round turns.** On Anthropic the conversation prefix carries rolling cache breakpoints, so a long tool loop pays the discounted cache-read rate on its history instead of the full input rate every round; cached-usage accounting is extended across providers (OpenAI, xAI, Moonshot, MiniMax, Zhipu, Google report their automatic cache hits into the same usage buckets), and `app.log` gets one `Prompt cache: …` summary line per exchange so the saving is visible.
- **Long pauses no longer throw away the prompt cache on Anthropic.** The cached prefix — your system prompt plus the tool definitions, often around 100,000 tokens — is now held for an hour instead of five minutes, so coming back to a conversation after a coffee, a meeting, or a Team Mode delegation that took half an hour still reads that prefix from cache at the discounted rate rather than paying full price to rebuild it. Previously any gap over five minutes re-billed the whole prefix from scratch. The rolling breakpoints on the conversation itself stay on the five-minute tier, because they are replaced every round and the longer tier costs more to write. Nothing to configure.
- **Prompt-cache write spend falls further, and the tail cache now tunes itself.** Deferred context-protection stubbing applies once at the end of an exchange instead of once per tool round, and pruning batches into larger, less frequent steps instead of firing on consecutive exchanges — both previously rewrote (and re-billed) the cached history far more often than the model actually needed. Team Mode specialist tasks now log their own `Prompt cache: …` hit-rate line, so that previously unmeasured spend is visible too. Whether the very end of a conversation earns the 1-hour cache tier is no longer a fixed rule: Codayak scores each choice against what actually happened next and nudges itself towards whichever tier your session's pace calls for. Nothing to configure.
- **Team Mode: a specialist now re-dials after the leader times its link out.** When a leader dropped a quiet peer after a sleep it parked the peer for a 10-minute re-admission window — but its teardown closed the link with the same clean 'Closing' frame as a deliberate session end, so the specialist stood down instead of re-dialling and the team died silently. The leader's park-for-reconnect teardown now closes with a distinguishable 'ReconnectExpected' frame, and — defensively, covering a leader crash too — the specialist treats ANY dropped link whose handshake completed as reconnectable unless it was explicitly told the session is over, engaging the existing fast-burst + long-tail retry schedule. The specialist's window also shows 'Connection to leader lost — retrying' the moment the link drops, and a suspend-sized heartbeat clock gap now logs why the peer timeout was deferred so overnight sessions are diagnosable from the log.
- **Team Mode follows the leader onto a new network.** When the leader's own address changes — switching Wi-Fi networks, tethering to a phone, docking — the advertised address is re-resolved within a couple of seconds (and re-checked every minute), the invite code on the Team page is regenerated to carry the new address, and the LAN advertisement is refreshed; previously a mid-switch 'localhost' address could stick for the rest of the session, leaving a stale invite code that no new peer could use. Already-connected peers are unaffected; a same-machine specialist that lost the LAN address falls back to the loopback address and re-admits in a couple of seconds, and its Team page now reports the address actually in use rather than the one it first dialled. The leader's chat pairs the existing '⚠ Team Mode peer link dropped…' notice with a '✔ Team Mode peer … reconnected — link restored after N s' notice when the peer returns.
- **Asking for the result of an interrupted-and-resumed delegated task no longer returns a blank.** `GetPeerTaskResult` on the original task id of a task that was orphaned and then re-dispatched now says so and names the replacement task and its current state, instead of an empty result that read as 'ran and produced nothing'.
- **Browser tests can answer JavaScript dialogs.** A page's `confirm()`, `alert()`, `prompt()` or `beforeunload` dialog used to be dismissed silently by the automation layer — so a Delete button guarded by *Are you sure?* always cancelled itself with no error. Dialogs are now accepted by default, `BrowserClick`/`BrowserClickAt` take an optional `dialogResponse` (`accept`, `dismiss`, or text to type into a prompt), and every dialog answered is reported in the tool result.
- **Patches land at the file's indentation.** When a patch's text was located by indentation-tolerant matching, the replacement was written with the model's indentation rather than the file's — new lines inside an indented block could land at column 0 (seen in tab-indented SQL). The replacement is now re-indented to the file's base indentation, keeping its own relative indentation; a patch whose indentation already matched is written byte-for-byte as before, and the result line says when re-indentation happened.
- **Trust Engine budget skips report `N/M files`** for the judged security review as they already did for spec compliance.
- **A rejected memory note is now explained, not hidden.** When the model tries to save a learning-memory note and it is refused — malformed block, blank title or resolution, too short, or a predicted confidence below the floor — a short 'Memory note NOT stored — …' notice appears in chat with the reason, and the model is told the same on its next turn so 'why wasn't that saved?' gets the real answer. A mere mention of memory notes in prose no longer triggers the notice. The reflection prompt's JSON template now includes the `predicted_confidence` field it previously only asked for in prose, and a note that omits it is reported as unrated rather than as low-confidence.
- **An edit changes only the lines you asked for.** PatchFile and CreateDocument (overwrite) could re-indent code outside the edited span — nested ternaries, fluent chains and multi-line argument lists were flattened in methods nobody touched. Bytes outside the edit are now written back unchanged, with the file's encoding, BOM and line endings preserved.
- **Tests run in Microsoft.Testing.Platform projects.** Repos that set `test.runner` to Microsoft.Testing.Platform in `global.json` (the .NET 10 / xUnit v3 default) previously reported '0 tests ran — FAILED' for every filter. RunTests and the Trust Engine now detect MTP projects, translate the filter to the runner's own syntax, and report a filter that matches nothing as `ZERO TESTS MATCHED THE FILTER` rather than a failure.
- **A missing .NET SDK is named.** When `global.json` pins an SDK that is not installed, build, format and dependency-audit steps now say `global.json requires .NET SDK X; installed: …` instead of 'build FAILED — 0 errors, 0 warnings'.
- **Launch smoke no longer fails web projects.** ASP.NET and other web/service projects have no desktop window, so the 'main window within 30 s' check is now reported as a non-gating note for them instead of a false NOT VERIFIED.
- **Trust report text agrees with itself.** A gate failure no longer prints a Low band beside a 100/100 score; the chat one-liner names the checks that actually failed; and automatic verification no longer says the code 'built green' after a failed build.
- **Your learning memory stays out of the chat.** Tool blocks show how many prior lessons were applied, not their titles, and raw `memory_note` JSON is no longer rendered in replies — safer for screen-shares and recordings.
- **`dotnet test` / `dotnet build` go through the right tools.** RunDotNetCommand now redirects them to RunTests (5-minute limit) and BuildProject, so large solutions no longer hit the 60-second command timeout.
- **No more `--no-sandbox` warning bar** in the Chrome window used for web search and browser testing.
- **The repo file count ignores build output.** The Working Folder caption no longer grows after a build (`bin`/`obj` were being counted); in git repositories, git-ignored files are also left out of the code map and codebase search.
- **Coordinate clicks are accurate with a dialog on screen.** DesktopClickAt now maps each window in a composited screenshot with its own scale.


### Added

- **Trust Engine v2.** Verification now reports seven fixed aims — compiles, tests & changed-line coverage, code style, UI style, security, spec compliance, learned lessons — with a trust band (High ≥ 85 / Moderate ≥ 60 / Low), a 0–100 quality score, `file:line` findings quoting the rule or requirement breached, and a NOT ASSESSED list. Build, test failures, Critical/High security findings, vulnerable packages and a failed app launch are gates: any one makes the run **NOT VERIFIED**. Build and tests are scoped to the blast radius of the session's changed files (whole solution at Deep).
- **Trust Engine token caps are the budget** — the two Settings caps are enforced at every depth (plus a 10% grace); recommended values per depth are shown beside the fields and filled in when the default depth changes. Values still at the old 8,000 / 32,000 defaults are raised once to 40,000 / 400,000. A judge that would exceed the cap is skipped and listed as not assessed rather than spending.
- **Trust Engine checks:** `dotnet format` + analyzer attribution against your coding-style rules with a residual-rules judge at Balanced/Deep; OWASP Top 10:2025 / CWE-mapped security scan (new empty-catch and swallowed-exception categories); `dotnet list package --vulnerable` dependency audit; judged security review of sensitive files; a fixed requirement checklist for spec compliance; lesson adjudication against Learning Memory; launch smoke of the built app (never attaches to a running instance); feature smoke scripts from `.coda/smoke/*.md` (Balanced: touched screens; Deep: all); integration test projects at Deep only; changed-line coverage threshold (70 %, warning by default, optional gate).
- **Trust Engine self-correction and escalation** — with **Auto self-correct on failed verification** on, a gate failure asks the model to fix and re-verify (1–3 iterations); at Light/Balanced a gate failure widens the blast radius once and re-runs only that gate's deterministic checks.
- **Settings → Trust Engine** rewritten: Depth, Token Budgets (with recommendations), Time Limit, Self-Correction, Audit & Reporting, Coverage, Smoke Scripts, Style Rules status and **Reset Trust Engine to Defaults**.
- **Settings propagate between instances** — a save in one running Codayak is merged into the others live (status line *Settings updated by another Codayak instance*).
- **`/secret` registers several credentials in one message** (one `/secret name value` per line; a stray non-command line refuses the whole message), and secrets now last the chat session — they survive the test browser closing or idling out and are wiped on Reset Session, `/secret clear` or exit.
- **Team Mode shows its port** — leader toolbar **👥 N peers (Port: NNNNN)** / **Team (Port: NNNNN)**, specialist **Team → :NNNNN**, Team page **Listening on host:port** and **Connected to <leader> at host:port**, and `ListTeamPeers` names each peer's endpoint.
- **Settings → Skills: Enable skills** — a master switch for the whole feature (on by default so existing skills keep working). Off, no skill is advertised or loaded, always-applied skills are not injected and Codayak cannot propose skills; the rest of the tab greys out and the list is kept, not deleted.
- **Settings → Skills: Allow Codayak to propose skills** (off by default, subordinate to Enable skills) gates the SearchSkills / CreateSkill / UpdateSkill tools; a per-skill **Always apply** flag injects that skill into every conversation instead of loading it on demand; a disabled skill shows an unticked box.
- **Attachment thumbnails** — hovering an attached image (including a pasted screenshot) shows a preview capped at 240 px with the path beneath.
- **Team Mode: peer edits reach the leader** — files changed by a delegated task appear in the leader's **Files Changed** panel with a diff and in the leader's Trust Engine scope.
- **In-app updater.** An **Update available** notice offers **Update now / Later / Release notes**. Update now downloads the installer to `%LOCALAPPDATA%\Coda\updates`, verifies its Authenticode signature (publisher TECHNICHE LABS PTY. LTD.) and only then asks to install; Later suppresses the same version for 24 hours.
- **Welcome window on first launch** (and whenever no LLM key exists): licence sentence with **View EULA**, LLM provider/key/model with **Get an API key**, web-search provider, and a **Get running fast** link. Replaces the old first-message chat bubble.
- **Web-search providers.** Settings → Web Search now offers **LLM Provider** (your chat provider's own search — Anthropic, OpenAI, xAI, Google — no extra key), **Serper**, **Tavily**, **SerpAPI** (surfaces Google's AI Overview first when present) and **Brave**, each with a **Get an API key** link. Google Custom Search is legacy: shown only to users who already have Google keys, retired 1 January 2027.
- **ReadImage** tool — the model can look at an image file (PNG/JPG/GIF/WEBP/BMP; SVG rasterised) from the repo, a reference repo/directory, the session output folder or a backup. Vision-capable model required.
- **EditImage** tool — masked erase/inpaint of a region (rectangles or a mask image) with everything else left unchanged; Stability and OpenAI.
- **DevOps tools take a `connection` argument** naming one of your configured Azure DevOps / GitHub connections; results are headed `Connection: …`, and each Codayak window keeps its own active connection.
- **ADO_AddWorkItemComment and GH_AddIssueComment** — the assistant can now reply in a work item's discussion / an issue's comment thread. The `ADO_UpdateWorkItem` guidance also documents the `System.History` route (with `comment`/`history` aliases) for posting a comment alongside other field changes.
- **Attach files to Azure DevOps work items.** `ADO_AddWorkItemComment`, `ADO_UpdateWorkItem` and `ADO_CreateWorkItem` take an optional `attachments` list — a screenshot just taken, a file attached to the chat, or a repo file. Images are embedded inline in the comment or description like a pasted screenshot; other files appear under the work item's Attachments tab. Any unresolvable name or failed upload refuses the whole call and nothing is posted. GitHub issues have no attachment API, so the `GH_*` issue tools say so and ask for a URL instead.
- **The rest of the work-item surface: read attachments, view history, add links, edit or delete comments.** `ADO_GetWorkItemAttachment` downloads an existing attachment (listed under RELATIONS with its size) into the session's `WorkItemAttachments/` folder and reads it — images shown to a vision model, text quoted with a truncation note, `.docx/.pdf/.xlsx` text extracted, other files saved and reported as binary; 25 MB cap, never executed. `ADO_GetWorkItemHistory` renders every revision chronologically (`State: Active → Resolved`, `Comment added (n chars)`, links/attachments added or removed). `ADO_CreateWorkItem` / `ADO_UpdateWorkItem` take a `links` list (Parent, Child, Related, Predecessor, Successor, Duplicate, DuplicateOf, Tests, TestedBy, Hyperlink) added in the same request after every target is verified to exist. Comments now show their `id=`, and `ADO_UpdateWorkItemComment` / `ADO_DeleteWorkItemComment` edit or remove one — deletion carries the same safety gate as deleting a work item. GitHub read parity where the API allows: `GH_GetIssueAttachment` (a file URL on GitHub's own attachment hosts), `GH_GetIssueHistory` (the issue timeline), `GH_UpdateIssueComment` / `GH_DeleteIssueComment`; GitHub has no link API, so the issue tools say to write `#123` or a URL instead.
- **Team Mode:** deliverables carry a **Complete / Partial / Blocked / Failed** status plus rationale, shown on the Team page; **↻ Resume interrupted tasks…** offers to re-dispatch tasks orphaned by a restart (never silently); specialists on vision models receive screenshots and read images as pictures.
- **Learning Memory:** memories also form after a success that follows repeated failures, and after repeated user corrections; every create/skip/inject decision is logged as a `[funnel]` line in `debug.log`.
- **Settings → Visual Models → Re-probe Edit Capability** — a button that re-checks, on demand, which of every keyed provider's image models can edit an existing image (normally discovered lazily on the first edit), with a status line while probing and a summary after (`Probed N model(s): X edit-capable, Y generate-only, Z unknown`). Each probe sends one real, billed generation per model, so it is a deliberate click — the tooltip says so.
- **Get an API key** links beside every LLM provider key box in Settings.
- **Restore Session shows where you left off.** After a restore, the last three exchanges of the newest selected transcript appear in the chat as a *Where you left off* recap with their original date and time — for your reference only; the model works from the session summary. Codayak's own tool output and internal prompts are excluded from the recap.
- Startup splash screen.

### Changed

- **Defaults for new installs favour maximum benefit at basic token cost.** A fresh install starts with **Learning Memory on** (retrieval is on-device and free; only storing a new lesson is a small background call) and the research panel's unprompted self-election at **User invoked**. Existing settings files are not changed on upgrade.
- **The .NET runtime now ships with Codayak.** The installer and the Microsoft Store package are self-contained, so there is no separate .NET 8 Desktop Runtime to install and the installer no longer checks for it (it still checks for WebView2). The download is larger as a result.
- Faster perceived start-up: heavy initialisation is deferred until the window is on screen.
- Web Search settings and the Get running fast guide rewritten for the new providers; vendor pricing and free-tier statements removed from the documentation.
- Trust Engine report layout: header chip, cost line, seven aim rows, SCOPE EXAMINED (with the budget-versus-used statement), FINDINGS, NOT ASSESSED, RECOMMENDATIONS, report path; the persisted copy under `.coda/verification/` carries the full evidence appendix.
- README and User Guide updated throughout for the above; the Trust Engine chapter and Settings reference rewritten for v2.

- **Requirements:** 64-bit Windows 10 (1809) or later / Windows 11 · .NET 8 Desktop Runtime · Microsoft Edge WebView2 Runtime · an API key for at least one supported LLM provider.

### What ships in 1.6.0

- **Seven LLM providers** on your own API keys — Anthropic, OpenAI, xAI, Google, MiniMax, Moonshot, Zhipu — switchable mid-conversation; **Fetch Latest** pulls each provider's current model list.
- **Whole-repo intelligence** — full source-code map (projects, types, members, dependency edges), skeleton fallback, dependency-aware working sets.
- **Read / modify / build / run tools** — patch, create, move, copy, delete (write-gated, backed up, diffed); MSBuild and `dotnet` build, test, run and scaffolding, including legacy ASP.NET projects via full MSBuild.
- **Trust Engine** — build → test → security scan → spec-compliance verification with a High / Moderate / Low trust band, confidence score, per-checker evidence and a saved report under `.coda/verification/`.
- **Real SQL** — `ExecuteSql` against SQL Server, PostgreSQL, MySQL/MariaDB, SQLite and Oracle with bundled drivers; writes gated and confirmed.
- **UI testing** — real Chrome (open / snapshot / click / type / wait) and Windows desktop apps via UI Automation; credentials pass as placeholders.
- **DevOps** — Azure DevOps and GitHub work items, wikis and line-level pull-request review under your team's rules; coding-style and PR-rule generation from your codebase.
- **Multi-file Coordinator** — plans a manifest and generates six-plus files in dependency order across worker sessions, with retry, resume and per-phase verification.
- **Research panel** — one question fanned across up to ten worker LLMs with distinct analytical framings.
- **Learning memory** — on-device embeddings (BGE-small-en-v1.5), hybrid retrieval, proactive lesson injection, confidence tracking, import/export.
- **Team Mode** — several Codayak instances collaborate over the LAN as an encrypted leader/specialist team (Ed25519, X25519, AES-256-GCM, pinned TLS, mDNS discovery); multi-repo development.
- **Skills**, **session continuity** with Restore Session summaries, **side-by-side diff** with rollback, **web search** via Google Custom Search in real Chrome.
- **Image generation** (OpenAI, Stability, xAI, Google) with reference-image editing; **text-to-video** (xAI) and **video analysis** (Gemini).
- **Speech** — TTS/STT across Deepgram, ElevenLabs, OpenAI, AssemblyAI and Azure; hands-free **Conversation Mode**.
- **Meeting Assistant** — live transcript with diarisation, live insights feed, meeting-type lens, end-of-meeting summary, optional batch re-diarisation.

### Known install notes

- **Run the installer as administrator** — a non-elevated install can stop with file-access errors ([#3](https://github.com/Techniche-Labs/codayak-releases/issues/3)).
- **Windows SmartScreen may warn on first run** until the new signing certificate earns reputation — *More info* → confirm publisher **TECHNICHE LABS PTY. LTD.** → *Run anyway* ([#2](https://github.com/Techniche-Labs/codayak-releases/issues/2)).
